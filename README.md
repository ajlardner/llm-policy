# llm-policy
My thoughts and rules for agentic coding and LLM usage

## ALL PROJECTS CONTAINING ANY AMOUNT OF LLM-GENERATED CODE ARE INDICATED AS SUCH WITH A DISCLAIMER AND A LINK TO THIS REPO IN THE README

## General Thoughts
LLMs are not particularly intelligent. They are not capable of writing complex code, let alone complex programs. Letting an LLM or a group of LLMs write and/or maintain a complex program is never going to go well. LLMs are good for answering questions with specific constraints, or if you write them the single most unambiguous design document that has ever existed and get lucky.

Simply, you cannot trust a non-deterministic system. Some people (read: AI labs) want you to believe it is close enough, and even one step away from, being intelligent enough that it doesn't need to be deterministic to be trusted with work that is currently trusted to humans. I have a hard time believing that.

LLMs and AI chatbots are also just very annoying to me. I am deeply annoyed by the way they write, both prose and code. I can instantly tell if your readme was written by an LLM and I'm then going to have very negative feelings about your project. It's like if you combined the worst opinions and typing patterns of every reddit user distilled through the most annoying posts they've ever written and then asked it to be your personal assistant. Even if it's getting things done, I hate it and I wish it didn't exist.

At least for the time being, I am ok with using LLMs to answer questions that I would be looking through search engine results otherwise, or for generating small amounts of boilerplate code that I'd likely be copying from StackOverflow or documentation anyways. For example, Pi Coding Agent did a decent enough job writing a [theme for itself](https://github.com/ajlardner/pi-coding-agent-config/blob/main/agent/themes/more-contrast.json) based on some very simple constraints, which is literally just JSON. If you need it to generate JSON, or to give you an example of code to understand a concept better, sure. But if you try do Openclaw you get AI slop every single time, guaranteed.

If you are willing to specify absolutely everything it needs to do at every step, and review *everything* at every single step, you can get some good results. You can also get a lot of use out of using an LLM or agentic coding tool like it's your senior dev coworker who is capable and has a ton of knowledge, but is also insanely overconfident and completely incapable of admitting when they are wrong or just don't know something. That person can be a great resource, but I don't really trust them. I wouldn't let that person push to prod on my application, and I don't think you would either. 

## Rules
- LLMs *NEVER* commit to main on any of my projects
- LLM generated code is *NEVER* committed to main or any release branch without extensive human review. I want to feel that I may as well have written the code myself. If I am doing less work than it would take to write the code from a StackOverflow answer, that is not acceptable for code I am responsible for
- Any branch that an LLM has directly committed code to will end with `_agent` and the commit authors of any commits will be clearly indicated with information about the LLM and the harness tooling used to generate the code

## Accountability
The human owner of the repository or the author / copyright holder of the software is responsible for all code generated by an LLM, just as they would be if they wrote it themselves.
